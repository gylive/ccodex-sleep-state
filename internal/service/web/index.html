采集时间与次数

不确定就用默认值。这里控制本地采集，不改变套餐额度、官方限流或上游 state 的真实寿命。关闭注入或使用中转时，这些设置不触发采集。

1–60 秒；不是正常回复的超时。
30–3600 秒；上游要求等待更久时，以更久为准。
120–3600 秒，从 state 签发时间计算；最后 30 秒不再接纳新请求。
至少 30 秒，必须小于有效期；不是每隔这么久刷新。
1–20 次；每次模型探测可能消耗额度。

高级设置（通常不用改）

请求上限与实际出口

默认 64 MiB，最高 128 MiB。解决本地 413，不会提高上游限制。越大越占内存；最多 4 个大请求同时处理，其余等待。

“自定义 IP”是选择你有权使用的代理端点，不是任意伪造公网 IP。采集节点与转发节点不同，不保证底层公网 IP 不同；节点名也不证明国家或家宽。跨出口使用 state 属实验功能。

外部代理模式会拒绝内嵌隧道协议节点；它不改变你使用网络的合规义务。开启前先在代理客户端加载订阅。

中转站连接助手

支持 Responses 兼容接口；只列出 Astra / Sol / Terra。中转按自己的 API key 转发，不强制采集 292，也不会凭 332 推断 Team 身份。

CCS / CC Switch 与中转站

自动接管会检查当前选中的 Codex provider。官方走官方认证，中转走自己的 API key；不会把官方登录凭据拿去试中转站。

注释和无关设置的改动不再导致整份配置报错。若 CCS 切换了上游或认证，服务会暂停转发，避免把凭据发错地方。点下面的检查按钮，保留当前选择后重新接管即可。

两种操作都会先备份当前配置和恢复记录。恢复旧备份会撤销之后的修改；不确定就选保留当前配置。

只读模式（--no-config）不会写入 Codex 配置；仍可保存本工具的采集和代理设置。需要接管 Codex 时，退出后用 setup 启动。切换完成后重启 Codex，让新会话使用新配置。

订阅与代理

有代理软件就填地址，有链接就导入。

本地已经开着 Clash 一类工具，就填它的 HTTP 或 SOCKS5 地址。没有，也可以直接导入订阅。

端口以你的代理软件为准。此处填写的是地址，不是 PowerShell 命令。

有些订阅会按客户端返回不同内容。只有订阅提供方要求时再填写，不会伪装模型版本。

按订阅标签筛选，不是出口地理位置验证。需要跳过证书校验的节点不会被接受。

保存会替换本服务现有出口来源，并留下配置备份；不会修改你的代理软件、系统代理或订阅原文件。

多个订阅合成一个代理池

可手动输入或粘贴订阅链接，每行一个；也可导入 TXT（UTF-8，最多 64 KiB）。最多 16 个来源、合并后最多 256 个节点；相同节点配置去重。任一来源失败时保留旧配置，不悄悄丢掉原池。

随机独立出口配合注入至少需要两个节点；已用/失败的不会自动回池。只想导入、不改变当前策略，请取消这个勾选。

仅导入你有权使用的来源。项目不提供订阅、节点、跨境线路或代购服务，不修改系统代理/TUN。节点不是经过验证的唯一公网 IP。

仅采集使用链式代理

采集 state：本工具 → 本地 Clash → 落地代理 → 上游。正常回复、压缩和模型列表：本工具 → 本地 Clash → 上游。

填写 Clash 实际 HTTP / SOCKS5 监听地址。留空保留已保存值；本地端口须能连接落地代理。 每行一个出口；支持 user:passwd@host:port，@ 前不用加反斜杠，也支持完整代理 URL。空行和 # 开头的行会忽略。留空保留已保存出口。

此模式仅供本工具使用，无需修改 Clash 规则或系统代理。开启后暂停原代理池来源、关闭随机出口及用后移出；关闭后恢复原来源，出口策略仍为采集同出口。账号密码保存在本机服务配置及备份中，不在面板回显。

通过落地出口采到 292，不保证换回本地 Clash 出口后仍可使用。采集仍遵守冷却及 401/403/429 停止规则；中转/API 通道及关闭注入时不采集。该模式无法让原本不能访问上游的本地代理独立完成正式回复。

节点生命周期

可用、已用、失败，分开管理。

记录按节点配置标识，不按国家名或公网 IP。已用/失败节点不会自动回池；重新导入相同节点仍保留记录。清理是停用，可再次手动放回，不修改订阅地址。

单节点重试只探测选中节点一次，失败后可在冷却结束再点。不读取登录文件、不跳过 401/403/429、不自动重放正式请求。主用仍可用时，成功的新值可作为备用。

遇到问题

先看是哪一层没通。

发给群友或 AI 的排查结果

只导出请求次数、状态码和配置状态，不导出密钥、订阅、对话、配置路径或 state。

本地 503：还没有合格 state

如果错误代码是 state_unavailable，说明服务没有拿到符合当前规则的票，不等于官方挂了。先看出口能否连接，再看会话状态。需要先正常用 Codex 时，可以主动关闭注入；程序不会偷偷帮你切换。

上游 503 / 502 / 超时

出口连接失败和上游拒绝不是同一回事。先测试你正在使用的出口，确认代理进程和端口。不要连点重试：真实请求可能已经执行，程序不会自动重发一次生成来赌成功。

unfinished config transaction

常见于直接关闭终端或系统异常退出。新版本会先核对文件：没被改动的旧接管配置可以安全恢复，再重新接管；如果 CCS 或你自己改过，保留备份和恢复记录，不覆盖新内容。

有代理地址，为什么还是直连？

旧版仅设置 CCODEX_PROXY 环境变量还不够，配置也要引用它。现在直接在「订阅与代理」选择代理、填地址并保存。当前服务不需要知道你以前在哪个终端设置过变量。

中转站为什么不能开启注入？

普通 Responses 中转未必提供官方 turn-state。此版本对中转采用不注入转发；不会拿官方账号去给中转打票，也不把一个 HTTP 200 宣称成改善了降智。

401 / 403 / 429

账号登录、访问权限或额度需要在 Codex / 服务提供方处理。管理面板不会用换出口来绕过这些限制。不要把 auth.json、订阅链接或完整日志发到群里。

Astra · Sol · Terra。尝试改善使用体验，不保证消除降智或限流。
