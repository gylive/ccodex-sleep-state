# 把自己的订阅或代理接进来

> 本页描述 v0.4.0 的代理池功能。已有 v0.3.1 包不会自动获得这些按钮。先看[发布与升级说明](release-v0.4.0.md)。

有订阅链接，直接导入订阅；已经有可用的 HTTP 或 SOCKS5 代理，也可以只填代理地址。它们都只给这个程序用，不会改变其他应用的网络设置。

Clash/Mihomo 订阅读取顶层 `proxies` 里的实际节点，规则、DNS、TUN 和代理组不一起导入。如果拿到的是只有 `proxy-providers` 的配置，需要换成包含节点的订阅。

## 先用面板，少敲几行命令

启动 `setup`（已有配置也可 `serve`）后，打开终端显示的管理面板，用同一终端的管理口令进入。到“订阅与代理”选来源，填地址或文件路径，测试通过后点应用。已经开着代理软件的，通常直接填本地 HTTP / SOCKS5 地址最省事。

这里有两个不同的测试：

- **来源测试：** 读取或下载、解析、构建出站。不会发送模型请求，也不证明节点能连通。
- **路由连接测试：** 通过指定出口给所选上游发不带登录信息的请求。收到 HTTP 响应只说明网络有回应，不证明能采到符合当前个人 / Team 规则的 state。

### 多个订阅：手动粘贴和 TXT 都可以

到「订阅与代理」的多订阅导入区：

1. **直接输入或粘贴**订阅链接，一行一个；也可以选 UTF-8 的 `.txt`，文件内容会先填入同一个输入框，供你检查。
2. 通常保留「追加到现有来源」。确实要换掉整组来源时再取消勾选；替换不会修改服务商的订阅。
3. 通常保留「导入后启用随机出口＋用后移出」。导入后就能使用代理池，不必再进高级设置；追加时保留高级设置中已选的固定出口，替换整组来源则需要重新选固定出口。取消此项不会主动启用池策略。
4. 点「先检查所有订阅」。成功只说明能读取、解析，不会调用模型。
5. 点「备份并导入代理池」，看确认提示。旧服务配置会备份，旧 state 会清空，节点的已用/失败记录保留。

TXT 不是必需品；不会做文件也能直接粘贴。TXT 最大 64 KiB，支持空行、`#` 开头的注释和 UTF-8 BOM。重复的订阅链接会合并；多个来源中相同节点配置也会去重。仍受最多 16 个订阅、合并后最多 256 个出口的限制。

单一来源表单和多订阅导入区是两种入口，**单一来源表单仍替换整组来源，多订阅区由“追加”勾选决定**。任何来源保存都要等正在执行的请求结束；上游拒绝或限流时不会通过重建采集器清除暂停。想避免将订阅凭据写入服务 JSON，可用下面的环境变量方法。[完整面板教程](web-panel.md)

## 只在采集 state 时使用链式代理

源码新增「代理池 → 仅采集使用链式代理」。适用于已有本地 Clash，希望采集请求再经过一个或多个 HTTP / HTTPS / SOCKS5 落地出口的场景。

```text
state 采集：本工具 → 本地 Clash → 落地出口 A/B/C → 上游
正式回复、上下文压缩、模型列表：本工具 → 本地 Clash → 上游
```

在面板填写本地地址和一个或多个落地地址，落地地址每行一个；保存时可选择追加或替换整组：

- 本地代理：例如 `http://127.0.0.1:7897`，也可用 `socks5://127.0.0.1:实际端口`。端口以你的 Clash 设置为准。
- 落地出口：选择 HTTP（默认）或 SOCKS5，每行粘贴一个 `user:passwd@host:port`。分隔符 `@` 前不用加反斜杠。也支持完整的 `http://user:passwd@host:port` 等 URL。

程序按列表顺序把每个出口作为独立采集节点，得到合格 state 后停止；单个出口失败才继续下一个。重复地址会自动去重，最多 256 个。不要将落地账号粘贴到公开日志或聊天里。保存后面板清空输入框；再次保存时留空保留旧值。

「测试链式连接」只通过两层代理建立到当前上游的 TCP 隧道，不发送模型请求、不读取 Codex 凭据、不保存表单。通过不代表取得 292，也不证明实际公网 IP、模型可用性或跨出口 state 有效。

开启并保存后，原有代理池来源保留在配置中但暂停加载，随机出口、固定节点和用后移出策略关闭。关闭链式模式后重新加载原来源，出口策略仍为采集同出口；需要代理池策略时重新选择。修改模式会备份配置并清空旧 state，不清除上游拒绝或限流。

不需要修改 Clash 的配置、系统代理或其他应用。只需要本地 Clash 监听端口能连接落地代理。正式请求仍依赖本地 Clash 自身能访问上游；如果只有通过落地代理才能访问上游，单独链式采集不能解决正式回复的连接问题。

该模式仅改变采集连接。官方通道关闭注入后，以及 API / 中转通道，不会调用链式采集；正常请求始终使用本地代理这一跳。采集失败不会偷偷改为直连或跳过第二跳，原有严格/普通转发兜底和 401/403/429 停止规则继续生效。通过落地出口拿到 292 后，换回本地代理出口能否使用仍需独立验证。

本机 JSON 的新增字段如下，其他字段继续使用当前配置；不要把真实凭据提交到仓库。凭据和原配置一样保存在本机服务配置及其备份中，管理状态和日志不回显。

```json
{
  "probe_chain": {
    "enabled": true,
    "local_proxy": "http://127.0.0.1:7897",
    "exit_proxies": [
      "http://USER1:PASSWORD1@HOST1:PORT1",
      "http://USER2:PASSWORD2@HOST2:PORT2"
    ]
  },
  "egress_mode": "state",
  "egress_route": "",
  "pinned_route": "",
  "pool_enabled": false
}
```

## 本地订阅文件与本机订阅接口

面板选“本地订阅文件”，填完整路径；JSON 形式如下：

```json
{
  "direct": false,
  "subscriptions": [
    { "file": "C:\\Users\\你的用户名\\Downloads\\nodes.yaml" }
  ]
}
```

把示例路径换成自己的实际文件。macOS 用绝对路径。只读取普通文件，支持与远程订阅相同的 YAML / URI / Base64 格式；不会修改原文件，不允许与同条来源的 `url` / `url_env` 混用。

本机程序提供的 HTTP 订阅，在面板选“订阅链接”。地址用 `http://127.0.0.1:端口/路径`，IPv6 可以用 `[::1]`。HTTP 仅支持字面值回环地址，不接受 `localhost` 或局域网地址；远程订阅仍必须 HTTPS。

## 用订阅链接

订阅链接通常自带访问凭据，别贴到 Issue 或群里。下面用环境变量传给程序，不把链接写进配置。每次新开终端需要重新输入一次。

在 PowerShell 运行下面三行，再按提示粘贴订阅链接；输入内容不会显示，也不会写进命令历史：

```powershell
$secret = Read-Host "粘贴订阅链接" -AsSecureString
$env:CCODEX_SUBSCRIPTION = [System.Net.NetworkCredential]::new("", $secret).Password
Remove-Variable secret
```

编辑本程序 `config.json` 的这几项，其他项保留：

```json
{
  "direct": false,
  "proxy_urls": [],
  "proxy_envs": [],
  "subscriptions": [
    { "url_env": "CCODEX_SUBSCRIPTION" }
  ]
}
```

这是可以独立使用的最小配置；缺少的字段会使用默认值。接着在**同一个 PowerShell 窗口**执行 `check` 和 `serve`。环境变量不会自动传给之前打开的另一个终端，也不会跨重启保留。

macOS 默认 zsh 可以用：

```sh
read -rs 'CCODEX_SUBSCRIPTION?粘贴订阅链接：'
export CCODEX_SUBSCRIPTION
printf '\n'
```

也支持 `{"url":"https://HOST/PATH?token=TOKEN"}` 的本地配置形式，但明文文件更容易被同步、截图或误提交。不要同时填写 `url` 和 `url_env`。

远程订阅 URL 只接受 HTTPS；回环 HTTP 也可以接本机程序提供的订阅。最大 2 MiB，最多 16 个订阅，合并后最多 256 个出口。无效项会终止导入，并显示订阅/节点序号，不显示私有 URL 或节点名称。

**启动、`check` 以及面板里的来源/路由操作会按需读取订阅，不做后台定时更新。** 用面板应用新来源可热切换，旧 state 会一起清空；直接改 JSON 则重启生效。不要把订阅文件改了等同于服务已经重新载入。

## 下载到了配置，却没有节点？

有的订阅会按下载客户端的 `User-Agent` 返回不同内容。同一个链接，可能给一种客户端完整节点，给另一种客户端空的 `proxies: []`。程序现在会明确报“服务端没有提供节点”，不会把它误报为 Base64 格式错误。

如果你的链接在 Clash Verge 能导入，在这里却拿不到节点，可以给这一条订阅指定下载标识，并只选自己想用的协议：

```json
{
  "direct": false,
  "subscriptions": [
    {
      "url_env": "CCODEX_SUBSCRIPTION",
      "user_agent": "clash-verge/v2.4.2",
      "include_protocols": ["anytls"],
      "exclude_keywords": ["香港", "台湾", "臺灣", "台灣", "澳门", "澳門", "Hong Kong", "Taiwan", "Taipei", "Macau", "Macao", "🇭🇰", "🇹🇼", "🇲🇴"]
    }
  ]
}
```

这是按需使用的例子，不是所有订阅都要照抄。`include_protocols` 不填就不筛协议；`exclude_keywords` 对节点名称和服务器地址做不区分大小写的包含匹配。过滤发生在建立出站适配器之前，被排除的节点不会参与采集。

**名称筛选不是出口定位。** 节点叫“英国”并不能证明流量一定从英国出去。需要确认实际出口时，还要另做检查。

程序不会因为某个节点要求 `skip-cert-verify: true` 就关闭证书校验。可以通过协议筛选排除这类节点，或请服务商提供能正常校验证书的配置。

## 已有 HTTP / SOCKS5 代理

先在你的代理软件里找到实际监听地址和端口，确认代理软件还在运行。不要照抄别人的端口。

在 PowerShell 这样输入完整地址：

```powershell
$secret = Read-Host "输入 HTTP 或 SOCKS5 代理地址" -AsSecureString
$env:CCODEX_PROXY = [System.Net.NetworkCredential]::new("", $secret).Password
Remove-Variable secret
```

地址格式如下。`HOST`、`PORT`、`USER`、`TOKEN` 换成你自己的值：

```text
http://HOST:PORT
https://HOST:PORT
socks5://HOST:PORT
socks5h://HOST:PORT
socks5://USER:TOKEN@HOST:PORT
http://USER:TOKEN@HOST:PORT
```

端口需要明确填写。用户名密码里的 `@`、`:`、`#`、`%` 等字符要做 URL 编码。配置引用变量名即可：

```json
{
  "direct": false,
  "proxy_envs": ["CCODEX_PROXY"],
  "subscriptions": []
}
```

macOS 默认 zsh 输入方式：

```sh
read -rs 'CCODEX_PROXY?输入 HTTP 或 SOCKS5 代理地址：'
export CCODEX_PROXY
printf '\n'
```

然后在同一个终端运行 `check` 和 `serve`。

不含凭据的本地代理地址也可以直接放在 `proxy_urls`。多个 URI 按数组顺序加入出口池。启用 `direct` 会把直连作为第一个出口；只想走代理，请保持 `false`。

HTTP/HTTPS 代理使用 CONNECT 隧道。SOCKS5 由代理接收目标域名。程序不会把失败的代理悄悄降级成直连，也不自动继承 `HTTP_PROXY` / `HTTPS_PROXY`，以免你不知道实际流量走了哪里。

## 下载订阅本身也需要代理

节点还没导入时不能用节点池下载它自己。准备一个独立的 HTTP/HTTPS/SOCKS5 代理 URI 环境变量，然后设置：

```json
{
  "subscription_proxy_env": "CCODEX_SUBSCRIPTION_PROXY"
}
```

这个代理只负责订阅下载，不会自动成为模型请求出口。下载失败返回的是经过脱敏的错误；不会把带 token 的 URL 塞进日志。

## 订阅格式与协议边界

| 格式 | 处理方式 |
|---|---|
| Clash/Mihomo YAML | 读取顶层 `proxies`；JSON 形式也可由 YAML 解析器处理 |
| 逐行代理 URI | 每行解析；任一非空、非注释行无效则报错 |
| Base64 URI 列表 | 支持标准与 URL-safe 字母表，有无 padding 均可 |

支持 HTTP、SOCKS5、AnyTLS、SS、SSR、VMess、VLESS、Trojan、Hysteria、Hysteria2 和 TUIC。HTTPS URI 被映射为启用 TLS 的 HTTP 代理。URI 别名与具体可用参数取决于锁定版本的 Mihomo 转换器；不要把“支持协议”理解为支持任意订阅服务商自定义格式。

SSH、WireGuard、代理组、链式 `dialer-proxy`、绑定系统接口/路由标记、从订阅加载本地证书或私钥都不开放。`skip-cert-verify: true` 会拒绝，避免订阅顺手关闭 TLS 校验。需要这些配置的节点，请换成能在严格校验下连接的出口。

## 用过和失败的节点去哪了

多订阅导入时，保留默认勾选的「导入后启用随机出口＋用后移出」即可启用，不需要再找高级设置。追加来源时，已选的固定转发出口会保留。仅配置单个代理或尚未通过此入口启用的用户，仍保留原先兼容循环方式。

需要以后调整，可到「连接设置 → 高级设置」勾选「用过的节点移入已用/失败清单，不自动循环复用」，或点「填入独立随机＋用后移出」后保存。独立随机并注入 state 时至少需要两个不同节点；耗尽后要手动回收，不会无提示循环。

「代理池」分四个清单：

| 清单 | 说明 | 你可以做什么 |
| --- | --- | --- |
| 可用池 | 尚可加入本轮选择 | 选节点后只探测一次，或暂时停用 |
| 已用清单 | 已预留或使用过的节点 | 需要二次利用时手动放回 |
| 失败清单 | 本次采集或转发失败 | 先检查原因，修好后手动放回 |
| 已清理（停用） | 用户主动移出的节点 | 需要时恢复，不是永久删除 |

点「全选当前清单」，再选「选中项放回可用池」或「清理选中项」。这些操作**只改本地清单，不把节点写回远程订阅**。清理是可恢复的停用，也不等于删除订阅凭据。记录按匿名节点 ID 保存在本地 `pool-state.json`，重启不自动洗掉使用记录。节点配置身份不等于公网 IP 身份：两个节点可能共用同一个公网 IP，服务商更换实际出口也不保证会得到新 ID。

已用节点不会因为重新导入相同订阅而自动可用。池耗尽就补充你有权使用的来源，或在确认原因后回收；不会悄悄重复扫描失败节点或切成直连。

### 只想试一个节点

1. 先在 Codex 发一条短消息，让服务拥有这个模型的现有会话。
2. 打开「代理池」，读取列表，选择该会话。
3. 找到节点，点「只试这个节点」，阅读可能消耗额度的确认提示。
4. 看本次结果；如果正在冷却，等倒计时，不要连点。

一次点击最多发起一次该节点的短采集探测，不会自动换到其他节点。已有主用值不会因为点击按钮被强制替换；获得的候选可留作备用。按钮不是无限重试器：现有冷却、正在采集、401/403/429 暂停和已停用节点的限制仍然有效。

## 自己决定正常请求走哪个出口

「连接设置 → 高级设置 → 正常请求的出口」有三种选择：

| 选择 | 行为 | 注意 |
| --- | --- | --- |
| 兼容模式 | 使用采集 state 的节点；没有 state 时走首个候选 | 默认保留此行为，适合先把连接跑通 |
| 独立随机 | 有 state 时，从可用池中选另一个节点 | 至少需要两个不同节点；不是每次一定得到不同公网 IP |
| 用户固定 | 读取节点后选定一个固定出口 | 明确允许复用该已用节点；失败/停用后需要先处理 |

“自定义出口 IP”实际是选择你有权使用的代理端点，**不能填一个任意公网 IP 就伪造来源**。采集节点和转发节点不同也不保证真实公网 IP 不同。跨出口使用 state 是实验能力，可能因上游绑定要求失败，不承诺降低风控或改善回答质量。

旧「路由」页的固定方式同时限制采集和转发；新「高级设置」把正常转发出口与采集分开。保存高级设置会解除旧的单路由固定，备份配置并清空旧 state；保存前请看清提示。

## 只连接已经配置好的外部代理

不想在本工具中加载隧道协议，可以在「连接设置 → 高级设置」开启「外部代理模式」。先在自己已有且有权使用的代理客户端中配置，再把本地 HTTP/HTTPS/SOCKS5 地址填给本工具。直连也仍可使用。

这个选项会在运行时拒绝内嵌隧道协议节点。**发布包仍包含相关依赖和内核代码，不是已剔除内核的独立精简版，也不构成合规保证。** 程序不提供节点、不改系统代理、DNS 或 TUN；使用和发布仍需遵守所在地规则，详见[合规与使用边界](compliance.md)。

## 探测是怎么跑的

以下仅适用于官方 ChatGPT 通道且开启注入；中转 / API 通道和关闭注入的请求不执行这套采集。

1. Codex 的第一条合法受支持模型请求提供转发认证头。启动时对认证文件的只读分类，不会将其中的密钥交给探测器或面板。
2. 如果没有可用 state，依次从候选出口发一个很短的独立请求，不带原会话正文和旧 state。
3. 完成的响应里，封装、时间和块数符合配置基线的值才进入 active / ready；首条请求拿到可用值就继续，不必等备用值。
4. 默认兼容模式从该 state 对应节点转发；明确选择独立随机或用户固定时，按高级出口设置转发。
5. **新用户默认“拿到后固定使用”**：只要当前值仍可用，不因提前刷新窗口反复采集；失效、到期或形状不匹配后再获取。没有备用时可能短暂等待。已有配置未写新策略字段的，保留原先“提前备好下一份”的行为，可在首页主动切换。
6. 选择“提前备好下一份”后，后台在冷却和次数限制内准备备用。首页切换策略保留当前值，不等于清除缓存或延长有效期。
7. 正式响应出现不匹配形状时，不把该正文交给客户端；若有可用备用，为**下一条请求**提升备用。没有备用就等待后续受限获取。当前请求可能已计费，不会自动重放，也不承诺“零中断”。
8. 探测或正式请求遇到 401/403，会暂停这份凭据；遇到 429，按 Retry-After 和本地冷却时间暂停请求及探测，不通过切出口、换模型或回收节点继续请求。

这一步是在为后续 Codex 请求找可用的出口和 state。它会消耗模型额度，也会用到代理流量；遇到账号权限或额度问题，先处理对应问题，再继续。
